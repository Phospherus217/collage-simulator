# 《大学四年模拟器》选项消耗与得分定性化展示规范 v1.0

> 对应新要求：选项上不直接写具体消耗和得分，改用更自然的定性描述。  
> 适用范围：选择前的选项卡、选择后的结果反馈、历史记录、资源不足提示和正式版 HUD。  
> 核心约定：**前台隐藏精确值，后台保留精确值；叙事提示负责可理解，数值系统负责可计算。**

## 1. 改造目标

当前 Demo 在选项上直接展示“消耗 2 TU”“消耗 20 EP”，选择后又在历史记录中显示“social +8”“skill +5”。这种展示虽然便于调试，但会带来三个问题：

1. 玩家容易把大学生活事件理解成属性兑换菜单，只比较单位资源收益；
2. 精确数字提前剧透结果，削弱人物、承诺、风险和路线选择的意义；
3. `TU`、`EP` 和英文变量名打断叙事沉浸，玩家需要先理解系统术语才能做决定。

正式版应改成：玩家在选择前能判断行动大致有多忙、多累、偏向什么结果、存在什么风险，但看不到后台精确消耗和精确得分；选择后通过剧情反馈和定性总结理解后果。

本规范不删除 `cost` 和 `variable_delta`。它们继续留在事件数据中供引擎结算、平衡测试、自动化测试和 Debug 面板使用，只是不直接显示给普通玩家。

## 2. 信息分层

### 2.1 选择前：只展示行动、负担、倾向和风险

每个选项卡建议由四层信息组成：

```text
具体行动
时间投入 · 精力负担
可能带来的主要倾向
必要时显示风险或机会损失
```

示例：

```text
留下来接管核心模块，把项目完整救回来
占用较多时间 · 高负荷
有机会形成一份完整作品，也会明显压缩休息
```

不再展示：

```text
消耗 3 TU · 消耗 45 EP
Skill +15 · Delivery +18 · Health -12
```

### 2.2 选择后：先写发生了什么，再写定性变化

结果反馈顺序统一为：

1. 人物回应或事情进展；
2. 玩家实际获得、失去或推迟了什么；
3. 1—3 条定性变化摘要；
4. 若存在未来责任，明确告知“之后还需要做什么”。

示例：

```text
你删掉了非核心功能，重新分配任务后终于在截止前交出了可运行版本。
团队没有拿到最亮眼的评价，但项目避免了彻底失控。

项目推进：基本稳住
团队关系：经历了一次有压力的协商
本月状态：有些疲惫
```

### 2.3 Debug：允许显示全部精确值

开发和测试模式继续显示：

- TU、EP 的实际消耗；
- 每项状态的实际增减；
- 标记增删；
- 路线状态迁移；
- 未来事件 ID 与触发月份。

Debug 信息不得混入正式玩家界面。推荐通过单独开关显示，而不是让正式文案同时承担调试职责。

## 3. 时间投入的定性等级

时间描述可由后台 `cost.TU` 自动映射。正式界面只显示“几乎不占时间”等文字，不显示 TU 数字。

| 后台范围 | 前台标签 | 玩家理解 | 常见行动 |
|---:|---|---|---|
| `TU = 0` | 几乎不占额外时间 | 当场回应或无需另行安排 | 婉拒、简单确认、收藏资料 |
| `TU = 1` | 少量时间 | 能插入现有日程 | 一次沟通、短时旁听、整理材料 |
| `TU = 2` | 需要专门安排 | 会占用一个明显时间段 | 聚餐、约会、周末活动、系统复习 |
| `TU = 3` | 占用较多时间 | 会挤压本月其他行动 | 实习、竞赛攻坚、完整项目任务 |
| `TU >= 4` | 持续投入 | 接近本月核心安排 | 商业交付、考研初试、头部实习转正 |

若选项还会产生后续固定占用，应增加驻留提示：

```text
之后一段时间需要持续投入
```

不显示“每月锁定 3 TU”，精确驻留成本只在后台和 Debug 中出现。

## 4. 精力负担的定性等级

精力标签应同时考虑选项消耗和玩家当前精力，而不是只按固定数值写死。

### 4.1 基础负担映射

| 后台范围 | 前台标签 | 含义 |
|---:|---|---|
| `EP <= 0` | 有助于恢复 | 休整或能够补充当月状态 |
| `EP = 1—10` | 负担很轻 | 基本不影响本月状态 |
| `EP = 11—20` | 有些耗神 | 需要注意后续安排 |
| `EP = 21—35` | 负担较重 | 会明显消耗当月状态 |
| `EP = 36—50` | 高负荷 | 容易挤压休息和其他承诺 |
| `EP > 50` | 极高负荷 | 只有状态较好时才适合承担 |

### 4.2 动态风险提示

在基础标签之外，引擎根据“选择后剩余精力 / 当前精力上限”追加风险：

| 选择后的预计状态 | 追加提示 |
|---|---|
| 仍较充足 | 无额外警告 |
| 降至一半以下 | 做完后会比较疲惫 |
| 降至四分之一以下 | 会让本月状态非常紧张 |
| 将发生透支 | 以你当前的状态，这项行动很可能造成透支 |

玩家必须在行动前看到透支风险，但不必看到“还差 17 EP”之类的精确计算。

## 5. 得分与属性变化的定性等级

### 5.1 后台变化等级到前台文字

选择后的总结可按变化绝对值映射：

| 后台变化 | 正向表达 | 负向表达 |
|---:|---|---|
| 1—3 | 略有进展 / 稍有改善 | 略受影响 / 稍有下降 |
| 4—7 | 有所提升 / 得到改善 | 受到影响 / 有所下降 |
| 8—12 | 明显提升 / 进展明显 | 明显受挫 / 明显下降 |
| 15—22 | 获得重要突破 | 遭受重大影响 |
| 26 以上 | 形成阶段性转折 | 出现严重转折 |

前台不直接显示“学业 +10”。推荐写成玩家能理解的生活语言：

| 后台变量 | 推荐前台说法 | 不推荐说法 |
|---|---|---|
| `academic` | 课程掌握更扎实、成绩准备更充分 | 学业值提升 |
| `social` | 和同学更熟、进入了新的信息圈 | 社交值提升 |
| `romance` | 关系升温、彼此投入加深、关系出现距离 | 恋爱值增加/减少 |
| `family` | 家人更理解你的选择、家庭压力有所缓和 | 家庭值提升 |
| `health` | 状态恢复、身体明显透支 | 健康 +15 / -20 |
| `portfolio` | 多了一项可展示成果、作品更完整 | 作品集加分 |
| `research` | 研究训练更扎实、形成可复现成果 | 科研值提升 |
| `skill` | 专业能力更熟练、解决复杂问题的把握增加 | 技能 +8 |
| `delivery` | 更能独立收口、团队对你的交付更放心 | 交付力 +12 |
| `reputation` | 老师或团队更信任你、口碑受到影响 | 声誉值变化 |
| `focus` | 目标更清楚、注意力被多项责任分散 | 专注值变化 |
| `ai_depth` | 对相关技术的理解更深入 | AI 深度 +15 |

### 5.2 一次结果最多展示三条变化

后台可以同时改变多项数值，但前台只突出与事件最相关的 1—3 项，其余变化通过结果文本自然表达或静默结算。

推荐优先级：

1. 玩家能直接观察到的主要结果；
2. 明显的代价或风险；
3. 新责任、路线机会或人物关系变化；
4. 微小伴随变化可不单独列出。

例如某选项后台同时改变 `skill`、`delivery`、`portfolio`、`academic`、`health`，前台可以只写：

```text
项目成果：形成了一份完整的可展示作品
独立交付：进展明显
身体状态：明显透支
```

## 6. 选择前的“结果倾向”写法

选择前不能剧透精确结果，也不能承诺尚未确定的成功。倾向提示采用以下句式：

```text
更有利于……，但会……
可以保留……，代价是……
有机会……，结果取决于……
能够暂时……，但问题会被推迟到以后
```

合格示例：

- 更有利于融入宿舍，但会占用原本的个人安排。
- 可以先保留这条技术线索，是否继续推进取决于之后是否真正复现。
- 有机会维护项目评价，但团队关系可能受到影响。
- 能够释放本月负担，同时会错过这次实习转正窗口。

不合格示例：

- 社交大幅增加，精力小幅下降。
- 获得 20 分作品集。
- 最优选择，高收益低风险。
- 选择后必定进入 AI-Lab Deep 阶段。

## 7. 隐藏信息与不确定结果

以下内容不得在普通选项上提前展示：

- AI-Lab 隐藏阶段、隐藏成长值和线索计数；
- 后台标记名称；
- 保研、考研、工作路线的精确判定门槛；
- 成功概率；
- 尚未发生的录取、转正或获奖结果；
- 未来事件 ID。

可以用现实线索替代：

| 后台信息 | 玩家可见线索 |
|---|---|
| 声誉达到门槛 | 学长开始把更完整的任务交给你 |
| 交付记录不足 | 对方愿意让你旁听，但暂不交付核心模块 |
| 保研竞争力较高 | 导师认为你的材料“有机会冲一冲” |
| 精力不足 | 你看着本月排满的日程，知道再接任务会很吃力 |
| 隐藏路线关闭 | 后续群聊里不再出现针对你的试做邀请 |

## 8. 前台资源状态也建议改为定性显示

新要求主要针对选项，但为了避免选项不显示数字、顶部仍要求玩家精确心算，正式版 HUD 建议使用进度条和状态词。精确值可放入 Debug。

### 8.1 时间状态

| 当前可用时间比例 | 显示词 |
|---:|---|
| 70% 以上 | 安排宽裕 |
| 40%—69% | 尚有余地 |
| 10%—39% | 日程紧张 |
| 0 | 本月已排满 |

### 8.2 精力状态

| 当前精力比例 | 显示词 |
|---:|---|
| 75% 以上 | 状态充沛 |
| 50%—74% | 状态稳定 |
| 25%—49% | 已有疲惫 |
| 1%—24% | 接近透支 |
| 0 | 精力耗尽 |

如果项目仍需保留数字以方便部分玩家规划，可在设置中提供“精确资源显示”辅助选项，默认关闭。

## 9. 选项不可执行时的提示

不能只把选项置灰而不给解释，也不能暴露精确差额。统一使用以下提示：

| 原因 | 推荐提示 |
|---|---|
| 时间不足 | 当前日程已经安排不开 |
| 健康限制 | 你现在的身体状态无法承担这项行动 |
| 前置经历不足 | 目前还没有合适的切入方式 |
| 路线已关闭 | 这次机会已经不会再向你开放 |
| 已过截止期 | 对方已经结束本轮确认 |

对于资源不足事件，仍应保留至少一个可执行的协商、降级、拒绝或休整选项。

## 10. 现有界面改造示例

### 10.1 宿舍聚餐

改造前：

```text
热情参与聚餐！和室友畅聊大学憧憬
消耗 2 TU · 消耗 15 EP
```

改造后：

```text
跟大家一起去聚餐，主动聊聊彼此对大学生活的期待
需要专门安排 · 有些耗神
更有利于快速融入宿舍，也会占用原本的个人安排
```

选择后：

```text
一顿热气腾腾的聚餐让大家很快熟络起来。回宿舍时已经不早，但你开始记住每个人的脾气和家乡。

宿舍关系：明显熟络
个人安排：有所压缩
```

### 10.2 大作业救火

改造前：

```text
独自硬扛！通宵重构 B+ 树索引并独立答辩
消耗 3 TU · 消耗 45 EP
```

改造后：

```text
接管核心模块，自己把完整项目救回来
占用较多时间 · 高负荷
有机会形成完整作品，但很可能挤压睡眠和其他承诺
```

若玩家当前状态很差，额外显示：

```text
警告：以你当前的状态，这项行动很可能造成透支
```

### 10.3 体面退出 AI-Lab 试做

改造前：

```text
坦诚告知当前精力需倾斜课业与升学，体面婉拒
消耗 1 TU · 消耗 5 EP
```

改造后：

```text
坦诚说明当前安排，婉拒这轮试做
少量时间 · 负担很轻
能够保住已有信任，但会错过当前的入组窗口
```

### 10.4 健康休整

改造前：

```text
全面减负！周末去公园散步并执行规律早睡
消耗 2 TU · 消耗 -20 EP
```

改造后：

```text
砍掉非必要安排，完整休息一个周末
需要专门安排 · 有助于恢复
身体状态会得到改善，但部分进度必须顺延
```

不得向玩家展示“消耗 -20 EP”这种难以自然理解的负消耗。

## 11. 数据与实现接口建议

### 11.1 后台字段继续保留

现有字段照常用于结算：

```json
{
  "cost": { "TU": 3, "EP": 45 },
  "variable_delta": {
    "skill": 15,
    "delivery": 18,
    "health": -12
  }
}
```

### 11.2 增加可选的玩家提示字段

建议给选项增加 `player_hint`，用于承载无法从数值自动生成的叙事倾向：

```json
{
  "player_hint": {
    "intent": "有机会形成完整作品",
    "tradeoff": "会明显压缩休息和其他承诺",
    "risk": "当前状态较差时可能造成透支"
  }
}
```

其中：

- `time_level` 与 `energy_level` 优先由 `cost` 自动换算，避免作者文案和后台数值不一致；
- `intent`、`tradeoff` 由事件作者填写；
- `risk` 可以由作者填写，也可以由引擎根据玩家当前状态动态覆盖；
- 隐藏事件允许省略 `intent` 中会剧透路线的部分。

### 11.3 历史记录保存两套信息

引擎日志继续保存精确值，界面只读取定性结果：

```text
内部日志：skill +15, delivery +18, health -12
玩家记录：专业能力明显进步；独立交付获得重要突破；身体明显透支
```

这样既能支持平衡回放，也能保证正式体验不被数字主导。

## 12. 文案模板

### 12.1 普通选项模板

```text
【行动】动词开头，说明玩家具体要做什么
【负担】时间标签 · 精力标签
【倾向】更有利于……，但会……
```

### 12.2 不确定机会模板

```text
【行动】尝试、申请、沟通或提交材料
【负担】时间标签 · 精力标签
【倾向】有机会……，结果取决于现有准备和后续表现
```

### 12.3 拒绝或退出模板

```text
【行动】明确说明如何拒绝、退出或延后
【负担】时间标签 · 精力标签
【倾向】可以保留……，同时会失去或推迟……
```

### 12.4 危机止损模板

```text
【行动】缩小范围、请求介入、划定边界或停止投入
【负担】时间标签 · 精力标签
【倾向】能够避免最坏结果，但必须接受……
```

## 13. 特殊场景规则

### 13.1 恋爱

不使用“恋爱提升/下降”。关系投入增加不一定完全有利，应写为“关系升温”“彼此投入加深”“关系出现距离”“承诺压力增加”。

### 13.2 家庭

家庭变量代表支持和托底程度。前台写“家人更理解”“经济压力缓和”“家庭分歧加深”，避免含义正反混乱。

### 13.3 健康与透支

任何会造成透支的选项必须在选择前出现明确警告。休整不写成负消耗，而写成“有助于恢复”。

### 13.4 考研、保研与工作

选择前只能提示“更偏向哪条准备方向”和“会放弃什么窗口”，不能显示精确录取分、门槛和结局判定。

### 13.5 AI-Lab

隐藏阶段不出现“AI-Lab 路线值增加”“即将解锁 Deep”等提示。玩家只看到学长态度、任务难度、是否得到下一次交流机会等现实反馈。

## 14. 验收标准

- [ ] 正式选项卡不显示 TU、EP 和任何精确属性增减。
- [ ] 每个选项均有时间投入和精力负担的定性标签。
- [ ] 高负荷或可能透支的行动有动态风险警告。
- [ ] 每个选项有一句可理解的收益—代价倾向，不使用“高收益低投入”等游戏化判断。
- [ ] 选择后先展示剧情结果，再展示不超过三条定性变化。
- [ ] 历史记录不显示 `social +8`、`skill +5` 等英文变量和数字徽章。
- [ ] 隐藏路线、标记、门槛、概率和未来事件 ID 不出现在玩家界面。
- [ ] 后台仍完整保留精确值，Debug 可查看全部计算过程。
- [ ] 禁用选项给出自然语言原因，并至少保留一个可执行的低负担方案。
- [ ] 作者提示与后台数值通过自动检查，避免出现“负担很轻”却实际消耗极高的矛盾。
