# 《大学四年模拟器》统一事件模板 v1.0

> 负责人：3号（事件系统与内容接入）  
> 适用范围：学业、社交、恋爱、家庭、健康、工作、考研、保研、AI-Lab及公共内容  
> 对接依据：1号月度循环、分支逻辑、未来事件队列、路线状态机和毕业简历收口规则

## 1. 使用原则

1. 所有正式事件必须使用本模板，不得因任务包不同而删改字段名称。
2. 不适用的字段填写“无”，不得留空；尚待其他成员确认的内容填写条件编号或“待2号/4号确认”，不得自行编造数值或路线规则。
3. 一个事件只能有一个主要“事件类型”。“强制事件、后续事件、公共事件”分别作为执行方式、来源和所属任务包表达，不另立事件类型。
4. 重要选择至少留下状态变化、记录、未来事件、路线影响、隐藏成长或长期经历中的一种可追踪结果。
5. 事件ID一经登记不得改名或复用。废弃事件保留ID并标记“已废弃”。

## 2. 事件编号规则

格式统一为：

```text
任务包前缀_三位流水号
```

| 前缀 | 中文任务包 | 示例 |
|---|---|---|
| `AC` | 学业 | `AC_001` |
| `SO` | 社交 | `SO_001` |
| `RO` | 恋爱 | `RO_001` |
| `FA` | 家庭 | `FA_001` |
| `HE` | 健康 | `HE_001` |
| `WK` | 工作 | `WK_001` |
| `GE` | 考研 | `GE_001` |
| `RE` | 保研 | `RE_001` |
| `AI` | AI-Lab | `AI_001` |
| `PU` | 公共事件 | `PU_001` |

编号要求：

- 流水号从`001`开始，在各任务包内独立递增。
- 编号只表示归属，不表示月份、类型、优先级或事件顺序。
- 跨月事件链中的每个事件拥有独立ID，通过“前置事件”“安排未来事件”和“经历链编号”关联。
- 内部标记使用`FLAG_任务包_含义`格式，并同时提供中文解释，例如`FLAG_SO_MET_LIN`（已经认识林同学）。
- 经历链使用`EXP_任务包_含义_序号`格式，例如`EXP_AI_LAB_01`。

## 4. 字段填写规则

### 4.1 条件字段

- “必须满足”中的条件全部成立才可进入候选池。
- “满足其中之一”为空时视为无需判断；非空时至少成立一项。
- 任一“阻止发生”条件成立，立即淘汰该事件，不再用更高优先级覆盖。
- 普通事件建议不超过1个时间条件、1—3个状态条件和0—3个记录条件。
- 状态条件优先使用2号定义的区间名或条件编号，例如`COND_ACADEMIC_GOOD`，不用作者自定的临时阈值。
- 路线条件只读取统一状态；事件选项不得让路线从“锁定”直接进入“进行中”等非法状态。

### 4.2 事件内容与选项

- 普通事件使用2—3个主要选项，关键选择事件使用2—4个选项。
- 自动结算的遗留结果可以没有选择，但必须在选项处写“无（自动结算）”，并填写结果和来源事件。
- 选项写具体行动，例如“留下来完成分工”，不写“学业+”“选择社交”等属性标签。
- 不把后台条件、隐藏阶段、成功概率和未来事件ID直接展示给玩家。

### 4.3 结果字段

- 每个选项分别结算，不能只在事件末尾写一个所有选项共享的模糊结果。
- 数值先使用2号的统一变化等级；精确数值由2号换算。
- 涉及工作、考研、保研或AI-Lab时，使用4号提供的路线条件和记录，由4号审核。
- 安排未来事件时必须同时写最早、最晚触发月份和过期处理，避免未来事件永久等待。
- 所有新增标记必须至少有一个明确的后续读取方，或明确只用于毕业回顾/审计。

### 4.4 重复、互斥与经历

- “第一次认识某人”“首次加入某组织”“路线正式选择”等不可逆事件必须为“仅一次”。
- 可重复事件必须设置文本变体或阶段差异；相同文本不得连续月份出现。
- 互斥事件使用互斥组，不用在多个事件里分别堆叠大量阻止条件。
- 能进入毕业简历的事件必须填写简历类型、经历链编号和阶段贡献。
- 同一长期经历的多个事件使用同一经历链编号，毕业时合并为一个条目；路线失败不删除已经真实完成的经历。

## 5. 最小完整示例（结构示意，非正式任务）

```text
【事件编号】SO_001
【事件名称】临时空出的排练位置
【所属任务包】社交
【事件类型】机会事件
【事件来源】普通生成
【执行方式】普通候选
【可发生月份】最早总月份：2；最晚总月份：6；过期处理：失效
【前置事件】无
【必须满足】社交状态不处于严重不足
【满足其中之一】参加过迎新活动 / 认识社团成员
【阻止发生】已经加入该排练；事件已完成
【路线条件】无
【隐藏条件】无
【事件优先级】P3普通；限时但不影响主线
【是否重复】仅一次
【互斥规则】无
【事件内容】社团排练前有人临时缺席，熟人问玩家能否顶上；当晚原本已有个人安排。
【选项A】调整安排，留下参加排练
【选项A结果】获得一次团队经历，消耗时间和精力，设置参与记录，并可能解锁后续合作事件。
【选项B】说明已有安排，帮助联系其他人
【选项B结果】保留原安排，获得较轻的关系反馈，不进入该经历链。
【状态影响】按2号变化等级填写
【新增记录】FLAG_SO_JOIN_REHEARSAL（参加过排练），由后续合作事件读取
【延迟影响】选项A安排后续事件，最早2个月后、最晚4个月后
【长期经历记录】选项A记录一次校园活动参与
【是否进入简历经历池】选项A：是；选项B：否
【简历经历类型】校园经历
【经历链编号】EXP_SO_CLUB_01
【简历阶段贡献】参与
【四年回顾记录】无
【结束后记录】按统一规则自动保存
```

此示例只演示字段关系。具体状态变化、资源消耗、月份合理性和正式文本仍须分别经过2号、1号与内容审核。
